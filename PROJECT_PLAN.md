# BARBER HOUSE — техническое задание и план разработки

> Учебный проект. Одностраничный сайт премиального барбершопа.
> Статус документа: **утверждён 2026-10-25**, ответы по умолчанию из раздела 7 приняты.

## 1. Анализ требований

### 1.1. Что мы делаем

Одностраничный сайт (landing page): вся информация на одной странице, меню прокручивает к нужному разделу. Цель сайта — **довести посетителя до кнопки «Записаться»**. Всё остальное (о нас, услуги, цены, команда, галерея) работает на эту цель: вызывает доверие и отвечает на вопросы «что умеют», «сколько стоит», «где находятся».

### 1.2. Требования и как мы их понимаем

| Требование | Что это значит на практике |
|---|---|
| Одностраничный адаптивный сайт | Один `index.html`. Корректно выглядит на ширине от 320 px (маленький телефон) до 1920 px (большой монитор). |
| Тёмный премиальный дизайн, золотые акценты | Почти чёрный фон, светлый текст, золото только на акцентах (кнопки, линии, цены, иконки). Много «воздуха», крупная типографика с засечками в заголовках. |
| Разделы Hero, About, Services, Prices, Team, Gallery, Contacts | 7 секций + шапка (header) с меню и подвал (footer). |
| Запись через внешний мессенджер, без реального адреса | Ссылка на мессенджер хранится **в одном месте** (конфиг). Пока ссылки нет — кнопка ведёт в раздел «Контакты» и показывает понятное сообщение. |
| HTML5, CSS3, JavaScript, без фреймворков | Чистый HTML/CSS/JS. Никаких React, Bootstrap, jQuery, сборщиков (Webpack/Vite), npm. |
| Без платных зависимостей | Только бесплатные шрифты (Google Fonts) и собственные SVG-иконки. |
| Подготовка к GitHub Pages | Только статические файлы, **относительные пути**, имена файлов латиницей в нижнем регистре. |
| Никаких выдуманных реальных отзывов, адресов, сотрудников | Нет раздела отзывов. Вместо имён мастеров — роли («Старший барбер»). Вместо адреса — явная заглушка. Фото людей не выдаём за сотрудников. |

### 1.3. Что НЕ входит в проект (чтобы не расползался объём)

- Онлайн-запись с выбором времени, база данных, личный кабинет.
- Админка для редактирования цен.
- Отзывы (по требованию — их не выдумываем).
- Мультиязычность.
- Отправка форм на сервер (у GitHub Pages нет серверной части).

## 2. Структура страницы

Порядок блоков сверху вниз и задача каждого:

```
┌─────────────────────────────────────┐
│ HEADER   логотип · меню · «Записаться» │  закреплён сверху при прокрутке
├─────────────────────────────────────┤
│ HERO      #hero                      │  первое впечатление + главная кнопка
│ ABOUT     #about                     │  кто мы, философия, 3–4 преимущества
│ SERVICES  #services                  │  карточки услуг (что делаем)
│ PRICES    #prices                    │  прайс-лист (сколько стоит)
│ TEAM      #team                      │  роли мастеров, без выдуманных имён
│ GALLERY   #gallery                   │  сетка фото: интерьер, инструменты
│ CONTACTS  #contacts                  │  адрес/часы/мессенджер (заглушки)
├─────────────────────────────────────┤
│ FOOTER   логотип · копирайт · пометка «учебный проект» │
└─────────────────────────────────────┘
```

**Почему Services и Prices — разные разделы?** Services продаёт эмоцию и показывает, что умеют (карточки с иконкой и описанием). Prices — сухая таблица для тех, кто уже решил и сравнивает цены. Так делают большинство барбершопов, и это удобно читать.

### 2.1. Содержимое разделов

| Раздел | Содержимое | Кнопка записи |
|---|---|---|
| Header | Текстовый логотип BARBER HOUSE, меню из 6 пунктов, кнопка «Записаться». На мобильном — «бургер». | да |
| Hero | Фоновое фото/градиент на весь экран, слоган, подзаголовок, две кнопки: «Записаться» и «Услуги и цены». | да (главная) |
| About | Короткий текст (2–3 абзаца) + 3–4 преимущества с иконками (например: «Классика и современные техники», «Премиальная косметика», «Атмосфера мужского клуба»). Цифры вроде «10 лет опыта» **не пишем** — это был бы выдуманный факт. | нет |
| Services | 6 карточек: мужская стрижка, стрижка машинкой, оформление бороды, королевское бритьё, стрижка + борода, детская стрижка. Иконка, название, 1–2 строки описания. | нет |
| Prices | Список «услуга ····· цена» с золотыми ценами, длительностью услуги. Пометка «Цены демонстрационные». | да |
| Team | 3–4 карточки: силуэт/монограмма вместо фото, роль («Арт-директор», «Старший барбер», «Барбер», «Барбер-стажёр»), специализация. | нет |
| Gallery | 6–8 изображений в сетке, по клику — увеличение (лайтбокс). | нет |
| Contacts | Адрес: «Адрес появится позже», часы работы (демо), кнопка мессенджера, место под карту (заглушка, без встраивания реальной карты). | да |
| Footer | Логотип, © год (подставляется скриптом), «Учебный проект. Все данные демонстрационные». | нет |

## 3. Структура файлов

```
barber-house/
├── index.html              ← вся страница
├── 404.html                ← страница «не найдено» (GitHub Pages подхватит сам)
├── css/
│   └── style.css           ← все стили, разделены комментариями по блокам
├── js/
│   └── main.js             ← весь интерактив + конфиг (ссылка на мессенджер)
├── assets/
│   ├── images/
│   │   ├── hero/           ← фон первого экрана
│   │   ├── gallery/        ← фото для галереи
│   │   └── og-image.jpg    ← картинка для превью ссылки в мессенджерах
│   ├── icons/              ← SVG-иконки (если не встраиваем прямо в HTML)
│   └── favicon/            ← favicon.svg, favicon.ico, apple-touch-icon.png
├── README.md               ← описание проекта, как запустить, ссылка на сайт
├── PROJECT_PLAN.md         ← этот документ
├── CREDITS.md              ← откуда взяты фото и шрифты (лицензии)
└── .gitignore              ← служебные файлы (Thumbs.db, .vscode и т. п.)
```

**Почему так:**
- **Один CSS и один JS файл.** Для лендинга этого достаточно, и новичку проще: всё в одном месте, браузеру меньше запросов. Внутри файла порядок держим комментариями-разделителями (`/* === HEADER === */`).
- **Папки `css/`, `js/`, `assets/`** — общепринятая раскладка, её поймёт любой разработчик.
- **`CREDITS.md`** — фиксируем источники фото. Это привычка коммерческой разработки: на чужие картинки нужны права.
- **Имена только латиницей, строчными, через дефис** (`hero-bg.webp`, не `Hero BG.JPG`). Windows не различает регистр букв, а GitHub Pages различает — `Hero.jpg` и `hero.jpg` для него разные файлы, и картинка «пропадёт» только после публикации.

## 4. Технические решения

### 4.1. HTML
- `<!DOCTYPE html>`, `lang="ru"`, кодировка UTF-8, `viewport` для мобильных.
- Семантические теги: `header`, `nav`, `main`, `section`, `article`, `footer`. Это помогает поисковикам и экранным дикторам (для незрячих).
- У каждой секции `id` для якорной навигации (`#services`) и один заголовок `h2`. На странице ровно один `h1` (в Hero).
- Ссылка «Перейти к содержимому» (skip link) для пользователей клавиатуры.
- Прайс — список определений или таблица (это действительно табличные данные).

### 4.2. CSS
- **Mobile-first**: сначала пишем стили для телефона, потом через `@media (min-width: …)` расширяем для больших экранов. Так код короче, а мобильная версия не становится «урезанной копией».
- **Точки перелома**: 576 px, 768 px, 1024 px, 1280 px.
- **CSS-переменные (дизайн-токены)** — цвета, шрифты, отступы задаются один раз в `:root`. Поменяли оттенок золота в одном месте — поменялся на всём сайте.
- Раскладка: **Flexbox** (строки, меню) и **Grid** (карточки, галерея).
- Класс-нейминг: **БЭМ** (`card`, `card__title`, `card--featured`). Понятно, какой стиль к чему относится, нет конфликтов.
- Плавная прокрутка через `scroll-behavior: smooth` и `scroll-margin-top`, чтобы закреплённая шапка не перекрывала заголовок раздела.
- Уважаем настройку `prefers-reduced-motion`: если человек отключил анимации в системе — не анимируем.

### 4.3. Палитра (предварительно)

| Токен | Цвет | Назначение |
|---|---|---|
| `--color-bg` | `#0E0E0E` | основной фон |
| `--color-bg-alt` | `#161616` | фон чередующихся секций, карточек |
| `--color-surface` | `#1E1E1E` | карточки, поля |
| `--color-text` | `#EDEDED` | основной текст |
| `--color-text-muted` | `#A0A0A0` | второстепенный текст |
| `--color-gold` | `#C9A54C` | акценты, кнопки, цены |
| `--color-gold-light` | `#E2C77E` | наведение на кнопки |
| `--color-gold-dark` | `#A8873A` | нажатие на кнопки |
| `--color-on-gold` | `#0E0E0E` | текст на золотом фоне |
| `--color-line` | `rgba(201,165,76,.25)` | тонкие разделители |

Золото на почти чёрном даёт контраст выше 8:1 — читается хорошо. Золотом **не** набираем длинные тексты — только акценты, иначе теряется «премиальность».

### 4.4. Шрифты (бесплатные, с кириллицей)
- Заголовки: **Playfair Display** (с засечками — классика, «дорого»).
- Текст: **Inter** (без засечек — хорошо читается; выбран на этапе 2).
- Подключение через Google Fonts с `display=swap` (текст виден сразу, даже пока шрифт грузится). Решено на этапе 2: Google Fonts (скачать файлы в проект можно позже, если понадобится).

### 4.5. JavaScript (`main.js`)

Сайт должен **работать и без JS** (меню и якоря — обычные ссылки). JS только улучшает удобство.

| Функция | Зачем |
|---|---|
| `CONFIG` в начале файла (`bookingUrl`, `messengerName`) | единственное место, где меняется ссылка записи |
| Подстановка ссылки во все кнопки `[data-booking]` | не нужно править 4 кнопки вручную |
| Заглушка, если ссылки нет | кнопка ведёт к #contacts и показывает «Онлайн-запись скоро откроется» |
| Бургер-меню | открыть/закрыть, закрытие по клику на пункт и по `Esc`, `aria-expanded` |
| Шапка при прокрутке | становится плотнее/темнее после первого экрана |
| Подсветка активного пункта меню | через `IntersectionObserver` |
| Появление блоков при прокрутке | лёгкая анимация, отключается при `prefers-reduced-motion` |
| Лайтбокс галереи | увеличение фото, листание стрелками, закрытие по `Esc` и клику на фон |
| Текущий год в футере | чтобы © не устаревал |

**Как будет устроена ссылка на мессенджер** (когда появится адрес):
- Telegram: `https://t.me/имя_пользователя`
- WhatsApp: `https://wa.me/79990000000?text=Здравствуйте!%20Хочу%20записаться`
- Ссылки открываем в новой вкладке с `rel="noopener noreferrer"` (безопасность).

### 4.6. Изображения
- Формат **WebP** (+ JPG как запасной для старых браузеров через `<picture>` — по желанию).
- Размеры: hero ≤ 300 КБ, фото галереи ≤ 150 КБ каждое.
- У каждого `<img>`: `alt` (описание), `width` и `height` (чтобы страница не «прыгала» при загрузке), `loading="lazy"` для всего ниже первого экрана.
- **Источники**: бесплатные стоки с открытой лицензией (Unsplash, Pexels) — только интерьер, инструменты, процесс без узнаваемых лиц; либо сгенерированные изображения. Все источники записываем в `CREDITS.md`.

### 4.7. SEO и превью ссылок
- `<title>`, `<meta name="description">`.
- Open Graph-теги (`og:title`, `og:description`, `og:image`) — красивое превью при отправке ссылки в Telegram/WhatsApp.
- Favicon в нескольких форматах.
- Разметку Schema.org `LocalBusiness` **не добавляем**: она требует реального адреса и телефона.

## 5. План разработки по этапам

Каждый этап заканчивается проверкой в браузере и коммитом в Git. Так у нас всегда есть рабочая версия, к которой можно откатиться.

### Этап 0. Подготовка окружения
**Делаем:** устанавливаем VS Code + расширение Live Server (автообновление страницы), Git, создаём аккаунт GitHub. Переносим проект из OneDrive в простую папку (см. риски, R1). `git init`, `.gitignore`, первый коммит с этим планом.

**Готово, когда:**
- [x] Папка проекта лежит вне OneDrive, путь без пробелов и кириллицы (например `C:\projects\barber-house`).
- [x] `git status` работает, есть первый коммит.
- [ ] Live Server открывает пустой `index.html` в браузере.

### Этап 1. Каркас (HTML-скелет)
**Делаем:** создаём все файлы и папки из раздела 3. В `index.html` — `head` (мета-теги), шапка, 7 пустых секций с `id` и заголовками, футер. Подключаем CSS и JS.

**Готово, когда:**
- [x] Структура файлов совпадает с разделом 3.
- [x] Все ссылки меню прокручивают к своим разделам.
- [x] HTML проходит валидатор W3C (validator.w3.org) без ошибок.
- [x] В консоли браузера (F12) нет ошибок 404 на CSS/JS.

### Этап 2. Дизайн-система (база стилей)
**Делаем:** сброс стилей, CSS-переменные (цвета, шрифты, отступы), подключение шрифтов, общие компоненты: контейнер, заголовок секции с золотой линией, кнопки (основная и контурная), карточка.

**Готово, когда:**
- [x] Все цвета и шрифты берутся только из переменных (в коде нет «случайных» `#ccc`).
- [x] Кнопки имеют состояния: обычное, наведение, фокус с клавиатуры, нажатие.
- [x] Кириллица отображается выбранными шрифтами.

### Этап 3. Header и Hero
**Делаем:** закреплённая шапка, логотип, меню, кнопка записи; первый экран с фоном, `h1`, слоганом и двумя кнопками. Мобильная версия меню (пока только вёрстка, без JS).

**Готово, когда:**
- [x] Hero занимает экран целиком на телефоне и на мониторе, текст читается поверх фона.
- [x] Шапка не перекрывает заголовки при переходе по якорям.
- [x] На 320 px ничего не вылезает за край экрана (нет горизонтальной прокрутки).

### Этап 4. About и Services
**Делаем:** текст о барбершопе и преимущества с иконками; сетка карточек услуг (1 колонка на телефоне → 2 на планшете → 3 на десктопе).

**Готово, когда:**
- [x] Сетка перестраивается на всех точках перелома.
- [x] Иконки — SVG, чёткие на любых экранах, одного стиля.
- [x] В текстах нет выдуманных фактов (лет опыта, числа клиентов, наград).

### Этап 5. Prices и Team
**Делаем:** прайс-лист с выравниванием «название ····· цена», длительность услуг, пометка «цены демонстрационные». Карточки команды с монограммами/силуэтами и ролями.

**Готово, когда:**
- [x] Прайс аккуратен на узком экране (длинное название переносится, цена не уезжает).
- [x] В команде нет имён и фото реальных людей.
- [x] Кнопка записи есть под прайсом.

### Этап 6. Gallery
**Делаем:** подбираем и оптимизируем 6–8 изображений, сетка галереи, `CREDITS.md`.

**Готово, когда:**
- [x] Каждое фото ≤ 150 КБ, формат WebP, есть `alt`, `width`, `height`, `loading="lazy"`.
- [x] Для каждого фото в `CREDITS.md` указан источник и лицензия.

**Готово, когда:**
- [ ] Все «реальные» данные явно помечены как заглушки — их невозможно принять за настоящие.

**Делаем:** все функции из таблицы 4.5.

**Готово, когда:**

- [ ] При пустом `bookingUrl` кнопки ведут к контактам и показывают сообщение; при заполненном — открывают мессенджер в новой вкладке. Проверены оба случая.

- [ ] При смене ширины экрана через 1024 px (например, поворот планшета) мобильное меню не «мигает» (замечено на этапах 3–4: отключать transition на время resize).

**Делаем:** проверка в DevTools на ширинах 320 / 375 / 768 / 1024 / 1440 / 1920 px; в Chrome, Firefox, Edge; по возможности — на реальном телефоне (Android и/или iPhone Safari).
